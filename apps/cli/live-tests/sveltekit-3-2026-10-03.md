# SvelteKit 3 migration audit — 2026-10-03

This branch migrates generated Svelte projects to SvelteKit 3.0.0 and Svelte 5.57.1. It is a draft migration: two upstream integration constraints prevent releasing it for every existing stack.

## Official sources and implementation

- [SvelteKit 3 migration guide](https://svelte.dev/docs/kit/migrating-to-sveltekit-3): configuration moves into the existing `sveltekit({...})` Vite plugin; the separate Svelte config is removed. The template adds package subpath imports for `#lib`, includes extensions on generated imports, extends `$app/tsconfig`, retains `$app/types` when adding Cloudflare types, and imports hooks from `@sveltejs/kit/hooks`. Node's minimum is 22.17. The selected adapter versions have Kit 3 peers.
- [Environment variables](https://svelte.dev/docs/kit/environment-variables): generated `src/env.ts` uses `defineEnvVars` for public inputs only. `static: true` preserves their existing build-time behavior. Convex and Cloudflare public access uses `$app/env/public`; Varlock still validates app-owned environment schemas.
- [Cloudflare migration](https://svelte.dev/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-cloudflare): bindings now come from `cloudflare:workers`. Fullstack auth and RPC handlers use that module through the app's typed environment export, rather than `event.platform.env`. Wrangler is a direct dependency for every Cloudflare Svelte app, satisfying adapter-cloudflare's peer. The obsolete platform declaration is removed.
- [Node adapter](https://svelte.dev/docs/kit/adapter-node): Docker and Prisma keep the existing adapter-node artifact. Prisma still uses its documented Compute custom build; this PR does not switch deployment APIs or claim a fresh remote deployment.
- [Varlock SvelteKit integration](https://varlock.dev/integrations/sveltekit/): non-Cloudflare apps retain the official Vite plugin. Kit reports its `transformIndexHtml` hook as unsupported; the selected auth/browser and build checks pass, but no dynamic public configuration is certified here. The warning is not suppressed.
- [evlog Vite integration](https://www.evlog.dev/reference/vite-plugin): CLI setup now inserts the plugin using the TypeScript AST rather than searching for the old exact `sveltekit(),` text. Runtime hooks use `$app/env`, native Cloudflare bindings and inferred auth values. Generated Svelte hook composition no longer casts the evlog handle or auth instance.

## Release blockers

1. **Better Auth 1.7.7 declares Kit `^2.0.0`.** [Published package metadata](https://registry.npmjs.org/better-auth/1.7.7). An isolated ordinary npm install with Kit 3.0.0 and Better Auth 1.7.7 fails with `ERESOLVE`. No force flags, legacy peer flags, dependency overrides, package patches or prerelease auth replacements were added. Passing Bun runtime checks does not establish upstream support.
2. **evlog 2.29.0 exports a Kit 2 error-handler signature.** Its published `evlog/sveltekit` types require top-level `status` and `message`. Kit 3's `HandleServerError` takes `kind`, `error` and `event`. The new generated-project type fixture assigns both exported hooks to Kit's public types and fails for `handleError`, with and without auth. This check remains enabled; no cast or wrapper conceals the mismatch. Sources: [Kit hook types](https://svelte.dev/docs/kit/@sveltejs-kit-hooks#HandleServerError), [evlog integration](https://www.evlog.dev/integrate/frameworks/sveltekit), [published evlog package](https://registry.npmjs.org/evlog/2.29.0).

## Validation

Twelve distinct generated fixtures passed ordinary installation, workspace typechecking and builds:

- Default Kit 3 frontend with Bun, npm and pnpm.
- Vercel and Cloudflare frontend builds.
- Cloudflare fullstack oRPC + Drizzle/D1 + todos, including infrastructure types.
- Desktop static frontend using the Tauri configuration. Native binaries were not compiled.
- Convex frontend configuration, using a synthetic URL; no live Convex account was exercised.
- Fullstack auth/Polar types, separate Hono auth/Polar types, and Hono auth/todo/AI types.
- Prisma frontend with pnpm, including isolated startup of `build/index.js` without `node_modules`.

The two evlog fullstack fixtures fail the stricter public hook type check described above. The earlier ordinary evlog build passed before adding that check; it is not counted as validated compatibility.

Two freshly generated local Bun fixtures passed browser and direct database checks in development and production: Svelte fullstack, and Svelte with a separate Hono server. These cover signup, sign-in, sign-out, protected navigation, persisted sessions and todo CRUD. Local runner records are `d5ec0812312a` and `fb58167eb69d`; they identify the built source fingerprint and the pre-commit base SHA. These are selected cases, not matrix certification.

Electrobun's native `prepare` command stalled and that packaging run was stopped. Static adapter generation is tested for Electrobun and Tauri; the completed desktop build covers Tauri's web output only.

Formatting/lint, generator types and CLI test types pass. The CLI unit suite passes: 843 passed, 70 skipped, zero failed (21,884 assertions). The updated addon file also passes on its own: 112 tests. The two generated evlog hook checks remain failures as documented above. No fresh Vercel, Cloudflare or Prisma remote deployment is claimed for this migration.
